# 观察页与数据口径

本页是观察页的界面与数据规范。演示先完成三轮固定引导与独立验收，再从终端或 Qoder 控制台继续自由对话；所有消息使用同一个 Session。Web 仅查看执行，不提供消息发送、报表或文件下载。已结束输入可回放历史事件，回放不重新执行任务。

## 页面怎么看

页面提供明暗主题，固定为上方架构、下方调试面板。默认按卡片实际高度分配空间；架构主体三列等宽，QCA占前两列，中列两个接口框等高。消息、事件和详情独立滚动，分隔条可拖动或用方向键调节，手动比例不会被刷新覆盖。窄屏在架构区内平移查看。

左侧只列当前Session的输入。选择消息可筛选或回放其记录；输入端口固定连向Session，滚动消息不会移动端口。Agent与Session的配置关系写成“使用Agent vN”。右侧Agent Sandbox保留Environment虚线映射；BYOC标记本演示资源部署在用户云账号中。

主区按实际职责排布：

- **Qoder Cloud Agents**：显示本次使用的 Agent 版本（如“使用 Agent v3”）、Skills、Session、Agent Loop / LLM、WorkQueue 与 Session events。配置面板展示本次已绑定信息，不拿后来修改的本地配置替代历史事实。
- **Self-hosted Environment**：表达云端 Environment 与外部执行端的逻辑映射，不把它画成另一台机器。映射到的 Analysis Sandbox 展示 Worker 与 Python；Browser Sandbox 作为独立工具实例置于映射外。Worker 通过 CDP 控制 Chromium，下载 CSV 再显式传给 Analysis；两个实例不共享文件系统。
- **调用追踪**：按消息和 `tool_use_id` 关联工具请求、实际执行与结果回传。点选事件后在固定标签中查看API、公开字段与时点，不再使用自动折叠的关联信息；`download_report` 内部的连接、筛选、下载和传输是工具内部步骤，不冒充模型规划出的多次调用。

图中不放固定协议序号。回放时仅在当前事件对应框体显示步骤号，与消息卡片的 n/N 进度同步；单步、点击定位与筛选不改变原始事件顺序。创建或核对 Environment 的事件高亮整个虚线框，工具事件高亮实际执行位置。框体可点选查看详情，标题可通过键盘操作。事件区的“事件范围”用于切换整个 Session 与选中输入。筛选隐藏当前回放步骤时保留画面和详情，并在进度旁提示。

页面显示实际记录的完整资源 ID，支持复制。Sandbox ID 打开同地域的 `sandbox-instances` 列表并复制编号，方便定位；不是单个实例的详情直达地址。仅提供能够验证的 Session 链接；缺少可靠直达地址时，提供控制台入口与复制 ID，不根据 ID 猜测深层链接。字段未记录时明确显示未记录。

界面统一使用14px分区标题、13px卡片标题、12px正文与等宽ID/代码、11px辅助信息。卡片正文和标识沿同一左边线排布，图标与标题垂直居中；API地址和对应说明成组呈现。

## 调试面板

默认“执行视图”按准备资源、各轮输入、会话与后台活动分组。一次工具调用合并请求、开始、完成与回传，展开可查看明确关联的内部步骤；模型请求仅用明确的开始事件 ID 配对。没有可靠关联的操作单独保留，不按相邻时间猜测归属。“原始事件”可查看未合并的记录。

持续操作显示时间条，创建资源、用户消息等事件显示菱形时间点。耗时来源分别注明本地单调时钟或 QCA 成对时间戳；执行中、记录不完整、未采集分别显示。跨执行端时间只帮助定位先后，不用来计算排队延迟。

详情固定为三个标签，刷新保留选中项和滚动位置：

- **输入 / 输出**：工具参数、代码、输出；实际采集的 API 则展示 request、response，各自包含允许公开的 headers、body，查询参数随 request 展示。
- **执行详情**：执行位置、状态、实际耗时与计时来源、关联 ID、开始/结束时间、API 路径、实际状态码和重试次数。未采集的 API 只做协议映射，不能冒充实际调用。
- **原始记录**：已保存的公开事件、Worker 记录或安全 API 投影 JSON，标明来源。这里的“原始”指保留已采集字段，不是未经处理的网络抓包。

新运行的指定 QCA 客户端按每次 HTTP 尝试记录实际请求、响应、状态码和单调耗时，写入绑定 run 的 `api-trace.jsonl`；Worker 在其执行现场另行记录，预览合并两者。SDK 创建实例的耗时单独标记，不虚构底层 HTTP 请求。旧运行保留已有公开事实，缺少的采集不补造。

采集采用接口字段白名单、完整凭证脱敏后再截断、大小上限和0600文件权限。认证头、Cookie、Work secret、Sandbox Key、二进制 Skill 上传和隐藏推理不会返回页面；未知接口仅保留安全元数据。原生/未知工具的参数及全部工具结果正文不由通用 API 采集公开，分别用 `input_omitted`、`content_omitted` 标记；工具代码和输出继续通过既有的业务工具、Read 路径白名单投影提供，避免 API 采集绕过内容边界。读取远端或本地记录时重新校验采集证明与归属。日志轮转、拒收或缺失标为部分历史，采集失败不改变业务请求的返回或重试行为。

## 两条链路，分别观察

**Work 管理链路：**WorkQueue 在 QCA 云端。Worker 为指定 Session 领取、确认并维持 Work 租约；每次工具调用不重新领取 Work。本例不推断 Work 的精确创建触发点。

**工具链路：**Worker 通过 `GET /sessions/{session_id}/events` 读取工具请求，将执行结果用 `POST /sessions/{session_id}/events` 回传。`Read` 读取 Skill 后，内容交给云端模型指导下一步工具选择；决策循环仍由 Qoder 执行。

观察器持续分页读取 Session 的公开事件，从游标接续，记录在 `var/results/<run_id>/live-session.sqlite3`，不覆盖三轮验收状态。终端和 Qoder 控制台提交的消息都可归入本次 Session；无需工具的回复不会被补造成工具调用。

## 哪些数字能说明什么

- **队列统计**来自 `GET /environments/{environment_id}/work/stats`，按 Environment 范围展示，不由工具条数、消息数量或动画估算。`workers_polling` 是最近 30 秒内不同 Worker ID 的轮询者数量，不能叫在线 Worker 数，也不能证明执行端健康。
- **Work 租约**显示实际领取、确认及成功续约记录。续约动效只由成功记录触发，不延长 Sandbox 生命周期。
- **工具状态**区分已观察请求、等待授权、执行中、执行完成和结果已回传。耗时来自实际开始、结束记录；缺失时间戳则不计算。
- **Sandbox 信息**来自实际实例查询或本轮已保存的身份记录；明确区分实时状态与历史信息，不套用当前模板配置冒充旧运行。

队列接口、会话事件或实例查询失败时，保留已有信息并注明不可用、过期或待确认；不显示虚构的零值、在线状态或成功动效。断线不等于实例销毁。查看历史输入时显示对应历史调用，停止实时执行动效。

## 发送、授权与结束

终端 `chat` 与 Qoder 控制台用于发送消息。先等上一轮结束；控制台不受本机提交锁约束。发送结果不明确时先检查会话，再用 `/retry` 或 `chat --retry` 沿用原编号重试；`/discard` 只清除本地重试记录，不撤回已提交消息。终端输入 `/back` 返回向导，再选择 `cleanup`。

本机预览仅绑定回环地址。Qoder PAT、Sandbox Key 与流量访问令牌留在本机或执行端，页面只接收脱敏后的公开投影；不把原始请求头、凭证或完整 Worker 环境返回浏览器。

三轮通过后保留固定验收快照。自由对话按当前工具能力运行，不再按默认 100/65/101 条判定；发布报表仍须经过文件与统计核算。Sandbox 到期或清理后停止执行；本例不承诺文件或进程恢复。

## 资源历史与消息回放

“资源”筛选包含 Agent、Environment、Session 的创建、核对和接续观测记录。新运行在创建成功时写本机账本；旧运行只从归属匹配的服务端对象 `created_at` 恢复创建事实。没有可靠时点时不补造。观察页接入现有资源时，核对 ID 与 Session 关联后记录“核对 / 接续已有”；这是观测接入，不是重新创建。

每条已结束输入下方的“回放轨迹”读取本 Session 的消息历史，可暂停、逐事件前后查看或返回实时。回放按事件顺序压缩间隔；显示的原始时间和耗时不变。顶部用简短状态区分实时与历史，控制项和缺失历史提示放在对应消息内；不重复铺设标题、图例和说明横幅。回放期间只读事件与已有工具记录，不发送消息、不调用工具，也不创建新资源。Session 级 `running` 有时先于下一条消息到达；没有明确消息归属时保留为全局事件，不把已完成输入改回处理中。

默认页面窗口与按消息历史分开：`GET /api/observer?message_id=<id>` 从本地会话记录读取该输入，最多 5000 条。原日志、输入输出或超限部分缺失时标为“部分历史”，不承诺超出已记录范围的完整回放。输入、执行开始、完成、QCA 接收结果仍保留各自记录，执行视图按关联 ID 合并。单轮回放只带明确关联本消息或工具的 API，不混入后续输入；执行视图和原始事件视图都对未发生步骤隐藏终态、输出和耗时。

成功观察到的安全执行快照保存在结果目录的 `execution-history.json`，0600 权限、原子替换、最大 8 MiB，并绑定 run/Session。离线时可读取该归档，或安全投影本次验收保存的 `worker.jsonl`（原始日志无法复核当时文件路径，故不公开其中的 Read 原文）；历史快照不会刷新心跳或假装在线。清理之后仍可查看已保留记录；实际可见内容以记录覆盖范围为准。
